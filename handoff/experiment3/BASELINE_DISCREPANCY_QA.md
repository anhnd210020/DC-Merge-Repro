# Supervisor Q&A: Oct 16 baseline discrepancy

## Why did the Oct 16 baseline differ from the current replay?

**The exact cause of the archived-versus-current difference is not established.** The largest recorded deltas are +0.158353 percentage points on validation for GTSRB in `dtd-eurosat-gtsrb-svhn`, and -0.148148 pp on test for EuroSAT in `stanford_cars-eurosat-gtsrb-resisc45`. These are current direct replay minus archived accuracy at the same selected `dc_rank` coefficient; the values and contexts are recorded in the [current-baseline manifest](results/experiment2/current_baseline/manifest.json) and [final verification](results/experiment3/final_verification.json).

The audit found no mismatch in the inputs it could verify: relevant runner/preprocessing code matches the Oct 16 handoff snapshot, current model/adapters/heads match their recorded Hub hashes/revisions, the dataset revision and split/config inputs match, and repeat preprocessing matched. Full image-byte identity and complete historical asset hashes were not available, so an archived asset mismatch cannot be ruled out absolutely. See the [replay audit](audit/replay-diagnosis.md#verified) and its [unverified items](audit/replay-diagnosis.md#unverified-or-unavailable).

**The lane-arithmetic fix addressed a separate, verified source of evaluation-path differences.** Before the fix, a uniform coefficient vector could be composed by scaling each materialized lane and summing them. The revised [`LaneMerge.compose`](code/lane_harm/lanes.py#L53-L74) uses `alpha * merged_update` when all coefficients are equal, preserving the direct global-`alpha` arithmetic path. The lane decomposition still reconstructs the merge with a maximum relative error of `1.7320007827947848e-7` ([verification record](results/experiment3/final_verification.json)).

That fix does **not** explain the remaining Oct 16 archived-versus-current deltas: the [audit](audit/replay-diagnosis.md#verified) confirms the current direct Experiment 2 replay does not use the changed `lanes.py` composition path. The Experiment 2 note’s 0.32 pp cross-check compared different arithmetic paths (`dc_official` versus full-lane composition), rather than repeated runs of one fixed path ([original note](results/experiment2/experiment2-results-note.md), [audit assessment](audit/replay-diagnosis.md#assessment)). It is evidence that arithmetic can affect borderline predictions, not a measured run-to-run tolerance for the Oct 16 replay.

## Is that difference normal?

**We cannot conclude that it is normal GPU evaluation variation.** In one controlled same-input GTSRB validation repeat on the current runtime, both passes had identical batches and labels and produced zero prediction flips. In a separate current-runtime diagnostic on identical inputs, AMP versus FP32 changed 30 predictions, while the old lane-summation path versus the fixed direct path changed 19. Those diagnostic flips had very small top-two margins, including exact ties ([repeat log](audit/same_input_gpu_check.log), [arithmetic/precision diagnostic](audit/sequential_path_diagnostic.json)). This makes numerical sensitivity near decision boundaries plausible. It does not identify which archived examples changed or prove that the Oct 16 difference arose from ordinary stochastic GPU variation.

The Oct 16 per-example logits/predictions and complete runtime, GPU, and driver record are unavailable. Consequently, the exact flips and the hardware/library contribution cannot be reconstructed. The evidence supports “plausible numerical sensitivity; historical cause unproven,” not “normal variation established.”

## Why are Experiment 3’s comparisons still internally consistent?

Experiment 3 used a separate current-environment baseline overlay: it kept each archived selected `dc_rank` alpha and substituted the current direct replay’s validation/test accuracies at that alpha, while preserving CT rows and the archived `compare/` directory. The overlay rule is documented in the [manifest](results/experiment2/current_baseline/manifest.json). The oracle reads its baseline records from the supplied `--exp2/compare` directory ([runner](code/lane_harm/run_oracle.py#L109-L149)); for the uniform baseline vector, the lane code uses the direct merge path described above.

All seven contexts reproduced this current baseline with maximum validation and test differences of **0.000 pp**. The original 0.1 pp check therefore passed against the agreed current-environment baseline; it was not relaxed for these comparisons. The archive/current differences remain disclosed as a historical limitation. Thus the oracle’s test deltas consistently compare its coefficient vectors with the baseline evaluated in the same current environment, but they do not establish exact reproduction of the Oct 16 run ([final verification](results/experiment3/final_verification.json)).
